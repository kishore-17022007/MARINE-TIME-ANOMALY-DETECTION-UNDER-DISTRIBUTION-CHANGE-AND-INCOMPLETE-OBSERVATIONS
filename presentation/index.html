Project overview

Adaptive maritime anomaly screening under changing conditions

A research prototype for identifying unusual vessel movement using NOAA AIS data, unsupervised learning, synthetic scenario testing, and an interactive dashboard.

NOAA AIS Isolation Forest LOF Synthetic benchmark
Verified samples 200,000 per experiment
Model bundle Fixed + Shadow robust ensemble
Evaluation Historical + Synthetic unlabeled + controlled

Challenge

Why this is difficult

  • Maritime movement is highly contextual and vessel-specific.
  • Historical AIS records are mostly unlabeled, so real accuracy is unknown.
  • Missing reports, irregular sampling, traffic shifts, and route variation distort signals.
  • A raw outlier score is not proof of intent, danger, or violation.

Research question

Can a reproducible unsupervised framework screen unusual vessel movement in a way that is auditable, interpretable, and honest about its uncertainty?

“The output is a review signal, not a legal or safety conclusion.”

Data

Verified NOAA Marine Cadastre source

  • Official daily vessel broadcast GeoParquet files for 2024.
  • One-day and seven-day experiments retained for final comparison.
  • Manifests verify schema, dates, row counts, and file integrity.
  • Samples capped at 200,000 rows with deterministic seeding.

Method

Model and feature pipeline

  • Chronological train/validation/test split.
  • Training-only median imputation and robust scaling.
  • Isolation Forest + novelty Local Outlier Factor.
  • Robust normalization and fused anomaly score.
  • Threshold from training score quantile.

Simulation

Scenario-based controlled evaluation

  • Speed jumps, deceleration, route deviations, and stops.
  • Missing-field masks and distribution-shift interventions.
  • Each injected case is paired with its original counterfactual.
  • Test labels are used only for controlled benchmark design.

Interface

Dashboard and simulator

  • Historical track replay with time-based browsing.
  • Model evidence: scores, thresholds, quality flags, components.
  • Scenario controls that recompute features for modified rows.
  • Session-local event log and score comparisons.

Conclusion

What the project proves and what it does not

  • It provides a reproducible, auditable research pipeline.
  • It distinguishes historical analysis from synthetic benchmark evidence.
  • It documents where the detector succeeds and where it fails.
  • It does not claim verified real-world maritime incident detection.

Future work

Expert-reviewed labels, broader vessel/time holdouts, contextual route features, and operational alert governance.

A good anomaly screen is transparent, measurable, and honest about what it cannot prove.
